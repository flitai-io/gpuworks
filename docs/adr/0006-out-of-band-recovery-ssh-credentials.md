# ADR 0006: 保存加密 SSH 凭证以支持带外恢复

日期：2026-08-24。状态：已接受。

节点首次接入成功后，server 保存其 SSH 端点与认证材料，认证材料使用既有 `auth.Secretbox` 和 server master key 做 AES-GCM 加密，并通过独立表与节点公开信息隔离。agent 控制连接失效时，恢复顺序固定为 agent 自重连 → server_dial 重拨 → SSH 带外探测；SSH 可达但 agent 未运行时先重启，仍未回连才沿用原 node token 重装。这样能恢复 agent 进程死亡和云实例非持久盘重置，同时避免为 SSH 再引入一套密钥管理系统。

## 权衡与后果

- server 被攻破后的攻击面从控制面数据扩大到所有已保存凭证的节点 SSH 权限；因此凭证 API 只写不读，响应仅给出端点和凭证类型标记，修改与清除要求管理员权限，数据库和 `data/master.key` 必须作为同一敏感边界保护。
- 凭证密文与 provider `creds_cipher` 采用相同密钥基线，降低运维复杂度，但 master key 丢失会同时导致两类凭证不可解密；备份与恢复必须包含该文件。
- SSH 使用持久化 TOFU host-key 校验。主机密钥变化会被当作不可达而持续退避，需要管理员核实后处理，不能自动放宽校验。
- 带外重装沿用原节点身份和 desired state；它不是重新纳管，也不会主动重建仍在运行的推理容器。注册型本地模型若随磁盘丢失，会对账为 absent 并阻止调度，等待用户重新登记。

## 未采用方案

- 只保存公钥指纹并依赖 agent 反连：agent 进程已经死亡时无法执行恢复。
- 不保存凭证、仅告警：维持了原安全边界，却无法满足无人值守恢复，尤其无法覆盖非持久盘重置。
- 保存明文凭证：没有理由低于现有云厂商凭证的加密基线，且会让数据库单独泄露即可直接登录全部节点。

## 修订（2026-11-04）：敏感文件权限

敏感文件默认仅所有者可读写（`0600`）。明确绑定本安装二进制和非 root 服务账户的 Linux systemd 安装可使用可信服务组（`0660`）；该组成员等价于拥有平台凭据访问权。macOS 与独立运行默认不向普通用户组授权。启动、安装和升级会收紧存量凭据、数据库及其 sidecar、已识别备份；临时数据库快照仅所有者可读。无法保护文件时拒绝继续，按错误路径修复所有者与服务组后重试。生成口令不写入服务日志。

新建或修改管理员密码须为 8–128 个 Unicode 字符、最多 512 字节，不能与用户名相同，并拒绝常见可猜口令、整段重复及序列；不强制大小写或符号组合，允许长口令短语。未指定时生成 24 字节随机值的十六进制口令。此策略不阻止已有账户继续登录。
