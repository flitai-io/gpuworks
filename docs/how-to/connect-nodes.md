# 接入、升级和卸载节点

把 GPU 主机接入已运行的 server。接入完成后，应能在**计算节点**中看到节点在线，并核对加速卡和运行时。

**适用场景**：接入自有 Linux GPU 主机、Apple silicon Mac 或云 GPU 实例；已有节点需要更新或退出服务时，可直接看[升级](#升级)、[维护节点](#维护节点停止调度与驱逐)或[卸载](#卸载)。

## 接入前准备

- server 已[安装并启动](install-server.md)，并有管理员账号可登录控制台。
- 节点与 server 至少有一个方向可达，按下文选择连接方向。SSH 只用于 SSH 安装，不是 Server 发起连接的必要条件。
- Linux 节点可使用 Docker；无法使用 Docker 时，agent 可使用内置 runveil。Mac 的系统要求及运行限制见 [Mac 节点](#macapple-silicon节点)。
- 节点的安装目录可写、可执行，空间足以容纳模型和运行时；没有 Docker 的节点还需允许文件名带冒号。已有 agent 的主机先看[重复接入](#重复接入同一台主机)，避免替换其他节点。

## 选择接入方式

云主机也可以使用手工命令或 SSH 向导接入。通过云平台入口安装时，GPUWorks 使用已同步的实例或物理机信息安装 Agent；安装完成并连接 server 后，主机会作为计算节点上线。

| 方式 | 适用条件 | 入口 |
|---|---|---|
| 手工命令 | 能在节点终端执行命令，节点可访问 server 的下载地址 | **添加节点 → 不支持 SSH**，生成安装命令 |
| SSH 向导 | server 可通过 SSH 登录主机 | **添加节点 → 支持 SSH**，预检查后安装 |
| 离线包 | 使用 Server 发起连接时手工安装，包括节点无法从 server 下载的情况 | **添加节点 → 不支持 SSH → Server 发起连接** |
| 公有云实例一键安装 | 已添加公有云账号并同步目标实例 | 在**外部平台**展开该账号，在实例列表点击**一键装 Agent**，见[公有云实例安装步骤](rent-cloud-gpus.md#安装-agent让实例出现在计算节点) |
| ZStack Cloud 物理机一键安装 | 已添加 ZStack Cloud 环境并同步目标物理机 | 在**外部平台**展开该环境，点击目标物理机的**一键装 Agent**，见[ZStack Cloud 安装步骤](onboard-zstack-cloud.md#安装-agent-并确认接入) |

### agent_dial 与 server_dial

在**添加节点 → 连接方向**中，按网络条件选择：

| 连接方向 | 网络条件 | 填写内容 |
|---|---|---|
| **Agent 发起连接**（`agent_dial`，默认） | 节点能访问 server；适合 NAT 后的节点，无需开放节点入站端口 | **管理节点接入地址**填节点可达的 server 地址，对应 `--server` |
| **Server 发起连接**（`server_dial`） | server 能访问节点的监听端口；不要求节点访问 server，也不要求 SSH | **Agent 监听地址**默认 `0.0.0.0:18800`；**计算节点接入地址**填 server 可达的 IP、域名或映射地址 |

Server 发起连接时，安全组或防火墙需为 server 放行入站 TCP。接入地址只填主机时使用监听端口；有端口映射时填映射后的 `host:port`。已有节点继续使用原监听地址，不随默认值改变。两个方向都不通时，先[打通网络](#节点与-server-网络不通)。

### 手工命令接入

1. 打开**计算节点 → 添加节点**，选择**不支持 SSH**。这是生成手工命令的入口，即使主机支持 SSH 也可使用。
2. 填写可选的**节点名称**，选择**Agent 发起连接**，核对**管理节点接入地址**。需要自定义安装目录或启动方式时，在**高级**中设置。
3. 点击**创建节点并生成命令**，再点击**复制命令**。此时节点显示为**连接中**，命令包含该节点专属 Token。
4. 在目标节点的终端执行命令，记录输出中的实际安装目录。安装完成后，按下文[确认接入结果](#确认接入结果)核对。

需要改变 driver、状态目录等参数时，查[安装脚本参数](../reference/cli.md#节点安装脚本-installsh)。重新执行安装会更新节点的连接配置；不要使用另一个节点的 Token。

### SSH 向导接入

1. 打开**计算节点 → 添加节点**，选择**支持 SSH**，填写节点名称、连接方向和对应地址。无需先创建节点取得 Token。
2. **SSH 目标**填写 `user@host[:port]`，或粘贴云厂商提供的 SSH 命令。向导只读取用户、主机和端口；`-i`、端口转发等选项不生效，跳板机 `-J` / `ProxyJump` 不支持。
3. 选择认证方式。使用默认的**平台密钥**时，复制表单中的授权命令，在目标机上以 SSH 用户身份执行；也可填写**密码**或**私钥**。目标 SSH 仅通过 PAM 等交互提示接收密码时，选择**键盘交互认证**并填写同一个密码字段；它与普通 SSH 密码认证是不同协议，显式选择后只尝试该方式。
4. 在**高级**中核对**安装目录**和**通过 systemd 启动**，点击**开始预检查**。按报告处理网络、目录和设备权限问题，再点击**安装 Agent**。
5. 查看安装结果；出现已有 agent 的替换确认时，先核对将受影响的节点。**安装命令已执行**不等于节点已在线，继续[确认接入结果](#确认接入结果)。

平台公钥也可在设置页的**SSH 密钥**中查看。授权命令中的 `<平台公钥>` 应替换为页面提供的完整公钥：

```sh
mkdir -p ~/.ssh && chmod 700 ~/.ssh && echo '<平台公钥>' >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys
```

键盘交互认证只支持一次非回显密码应答，允许有限的无问题信息轮次；不支持多问题、多次口令或 MFA。认证方式不匹配时，报告会提示核对目标 SSH 配置或选择键盘交互认证；网络不通、主机密钥变化仍需分别处理。

使用密码、键盘交互认证或私钥安装成功后，server 会尝试写入平台公钥，成功后只保留平台密钥；写入失败时才保存所填凭据。安装报告的 `SSH authentication` 和 `Platform key` 显示认证与公钥写入结果。预检查不写入公钥，只会为目录探测创建并删除临时文件。节点的 SSH 凭据编辑也提供相同认证选项，保存时同样尝试授权平台公钥。保留口令后重新打开会显示**密码**，表示保存的凭据类型；后续自动恢复会兼容普通密码与键盘交互认证，不要求重新保存。

### 离线包

1. 打开**计算节点 → 添加节点**，选择**不支持 SSH → Server 发起连接**，填写监听地址和接入地址，再点击**创建节点并生成命令**。
2. 点击**下载离线包 gpuworks-agent.run**，将文件传到节点；核对文件的 SHA-256 与页面显示一致。节点需要 `tail`、`head`、`gzip`、`mktemp`。
3. 在文件所在目录执行页面生成的命令。下面是默认监听地址的示例，`<节点 token>` 使用该页面生成的专属 Token：

   ```sh
   sh gpuworks-agent.run --token '<节点 token>' --connect-mode server_dial --listen '0.0.0.0:18800'
   ```

4. 等待 server 连接节点，按[接入结果](#确认接入结果)核对。

离线包包含 server 内嵌的 Linux / Mac agent 和安装脚本，自动选择匹配的平台；包里没有 Token。直接下载地址为节点接入地址下的 `/dl/gpuworks-agent.run`，校验文件为 `/dl/gpuworks-agent.run.sha256`，不从网关地址下载。server 升级后应重新下载离线包。

### 确认接入结果

回到**计算节点**，确认节点从**连接中**变为**在线**，进入详情核对加速卡型号、数量和运行时。节点仍未连接时，检查安装报告、节点的 `agent.log` 和[网络条件](#节点与-server-网络不通)，不要重复创建节点。

节点间同步、多机推理和服务流量使用的网络，见[配置节点网络](configure-networks.md)。

### 启动方式与后续重启

| 安装条件 | 启动方式 | 维护时注意 |
|---|---|---|
| Linux 有 systemd，且安装用户是 root 或有免密 sudo | **通过 systemd 启动**开启时，使用 `gpuworks-agent.service` | 开机自启，崩溃后自动拉起 |
| 关闭上述选项，或没有 systemd / 相应权限 | nohup 后台运行；命令行用 `--no-systemd` 选择 | 不随开机启动，进程退出后不自动拉起；使用 state 目录中的 `agent-restart.sh` 重启 |
| Mac | launchd | 不受 systemd 选项影响，登录及权限要求见下节 |

SSH 安装及云主机一键安装（包括云助手等命令通道）会记录实际安装目录，后续带外重启、重装沿用该目录和节点的启动方式。手工脚本接入没有这条目录记录，带外恢复按 `/opt/gpuworks` 处理；使用自定义目录或同机第二个 agent 时，应留意这一差异。

state 目录保存节点状态和连接配置，未单独指定时与安装目录相同。连接配置位于其中的 `gpuworks-agent.conf`，Token 不出现在进程命令行、systemd unit 或 plist 中。需要改配置时重新执行安装，文件和权限说明见[安装布局](../reference/install-layout.md#agent-配置文件)。

## Mac（Apple silicon）节点

Apple silicon Mac（M1–M5，macOS 15 及以上）可按上面的手工命令、SSH 或离线包流程接入，Intel Mac 不支持。server 可以在同一台 Mac 或其他主机上运行。

SSH 向导上传 agent 和安装脚本，不要求 Mac 从 server 下载。预检查核对 Apple silicon、macOS 版本和芯片。

安装前确认账户权限，决定 agent 是否能在未登录时运行：

| 权限与登录状态 | 安装结果 |
|---|---|
| 可使用管理员权限 | sudo 验证成功后安装为 LaunchDaemon，开机启动，但 agent 仍以安装用户身份运行。手工安装时可在终端询问密码；SSH 密码登录时，该密码也用于验证 sudo |
| 不使用管理员权限 | 手工命令追加 `--no-sudo`；SSH 密钥登录且无免密 sudo 时也走此方式。安装为 LaunchAgent，仅在该用户登录期间运行；没有图形登录会话时会报错 |

未指定安装目录时，无论是否使用管理员权限（手工命令与 SSH 向导相同），agent 都安装到安装用户的 `~/gpuworks`；早先的安装在 `~/gpuworks`、`/opt/gpuworks` 或 `~/.gpuworks` 留有 agent 时，按此顺序沿用该目录。同机控制面默认在 `~/gpuworks/server`，两者互不覆盖。

安装会等待 launchd 稳定启动；重装时若新任务被拒绝，会恢复原任务。Mac 同样支持控制台**升级 Agent**，确认与回滚边界见[升级指南](upgrade-and-compatibility.md#升级-agent)。

安装后，节点应显示 **host** 运行时和 **1 张统一内存的卡**。引擎作为宿主机进程运行，使用 Metal 环境包，不使用 Docker Desktop。

可用显存是 Metal 允许 GPU 常驻的部分，通常约占统一内存的 2/3–3/4，由 `iogpu.wired_limit_mb` 决定，平台不修改。vLLM 按 `gpu_memory_utilization` × 显存计算份额；Mac 可同时运行多个实例，需要并跑时按内存容量调整该值。

**Mac 不支持引擎休眠、多机推理与 KV 磁盘层。** 有实例运行时不会空闲睡眠，但合盖仍会睡。

### Mac 的环境与数据说明

- agent 将安装目录及另设的模型目录排除在 Time Machine 备份之外；Mac 之间可同步模型与环境包。
- TUN 代理开启时，上报实际网卡地址而非代理虚拟地址。引擎仅监听 `127.0.0.1`，不触发应用防火墙弹窗。
- 节点与实例终端均可用：节点终端使用 agent 用户的 zsh，实例终端使用实例的环境、HOME 和工作目录。实例终端没有容器隔离，关闭标签页会回收其中启动的进程。

## 安装目录检查

安装目录保存 agent、模型缓存和运行时数据；Linux 默认 `/opt/gpuworks`，Mac 规则见上节，可在**高级 → 安装目录**修改。SSH 预检查和安装报告会显示以下检查结果；云主机一键安装也按安装弹窗**高级**中的目录检查。按失败或警告项处理后再安装；目录尚不存在时，探测其最近的已存在上级目录。

| 检查项 | 可能状态 | 含义与处理 |
|---|---|---|
| Install directory | 通过 / 警告 / 失败 | **失败**：路径不是绝对路径、已存在但不是目录、不可写或挂载为 `noexec`。`noexec` 会使 SSH 安装在上传前失败；只有目录留空、默认目录不可写时才回退到 `/tmp/gpuworks`，需核对最终目录及重启后丢失数据的风险；显式填写的目录不可写时安装失败，不会换目录；Mac 上没有管理员权限时，提示留空目录以安装到 `~/gpuworks`。**警告**：探测未完成，先查看报告原因 |
| Install directory ownership | 通过 / 警告 | **警告**：文件系统拒绝 `chown`，udocker 工作负载会改用 agent 自身的用户运行。无 root 或免密 sudo 时不做此项检查；Mac 无需此项检查 |
| Install directory path access | 通过 / 警告 / 失败 | root agent 以专用用户 `udocker` 运行 runveil 工作负载，该用户必须能进入安装目录的每一级上级目录（`o+x`，或其所属组带 `x`）。某级上级目录不允许时（如安装在 `/root` 或 0700 的私有主目录下），每次启动都会以 `permission denied` 失败。详情给出第一个挡住的目录及其权限和属主，处理方式是执行 `chmod o+x <目录>`（只授予进入权限，不能列目录或写入），或改用其他安装目录（如 `/opt/gpuworks`）。**只有探测能确定以下全部成立时才是失败，并且 SSH 安装与云主机一键安装会在上传 agent 前停止**（API 返回 400 `NODE_INSTALL_DIR_UNTRAVERSABLE`）：SSH 用户是 root（agent 以 root 运行）；安装会用 runveil（安装显式选了 `udocker`，或未指定且 docker、nerdctl 都不可用，且架构为 x86_64/arm64）；会用专用用户（文件系统接受 `chown`，且 `udocker` 账号已存在或有 `useradd` 可创建）；该目录确实对该用户关闭（权限位不放行，且没有可能放行的 ACL）。其余情况是**警告**，详情写明哪一环不确定且不会阻止安装：SSH 用户不是 root（免密 sudo 时 agent 只有在 systemd 托管下才以 root 运行，nohup 安装以该用户运行，探测无法预知）、本机 docker 或 nerdctl 可用（agent 优先用它们，仅在其无法给容器提供 GPU 时才改用 runveil）、安装显式选了 docker/nerdctl、无法确认 `chown`、没有 `useradd` 且账号不存在（agent 会改用自身用户运行）、目录带 ACL。云主机一键安装不指定运行时，由 agent 按上述顺序自动选择。节点恢复重装一个已在该目录运行的 agent 时不受此阻止，仍只显示警告。安装目录自身由安装脚本开放（0711），不在检查范围内；非 root 且无免密 sudo、文件系统拒绝 `chown`（工作负载以 agent 自身用户运行）时不做此项检查；上级目录权限读不到时显示“未检查”，不会阻止安装；Mac 无需此项检查。装好之后节点诊断用 `runtime_state_untraversable` 报告同一问题 |
| Install directory filesystem | 通过 / 警告 | **警告**：网络或用户态文件系统，模型加载和引擎启动受其吞吐、延迟影响 |
| Install directory free space | 通过 / 警告 | **警告**：剩余空间低于 50 GiB。按镜像解包体积和模型大小预留空间，50 GiB 不是所有部署的容量保证 |
| Install directory file names | 通过 / 警告 / 失败 | 不允许文件名含 `:` 时，无可用 Docker 为**失败**，需换目录才能部署；有可用 Docker 为**警告**，镜像由 Docker 保存。不可写时不检查 |
| Install directory persistence | 通过 / 警告 | **警告**：容器可写层、`tmpfs` 或 `ramfs` 在重建或重启后可能丢失 agent、节点身份和缓存。可选目录时优先兼容的持久卷；云容器实例使用容器可写层时，实例重建后需重新接入 |

状态要结合详情判断：属主或文件名未检查、文件系统类型或剩余空间未知时，也可能显示**通过**。探测超时或输出不完整只给出 `Install directory` **警告**，不能据此断定目录有问题。报告展示文件系统类型和挂载点，不列完整挂载选项。

### 为什么 udocker（runveil）节点的安装目录不能放在网络卷上

runveil 将镜像层和解包文件放在安装目录下。RunPod `/workspace` 这类不支持冒号文件名的网络卷无法保存 `sha256:<hex>` 等镜像文件，会报 `Invalid argument`；不能因为它是持久卷就把运行时放在那里。

没有兼容的持久卷时，使用容量足够的本地容器盘，例如默认 `/opt/gpuworks`。镜像解包通常需要数十 GiB，还需容纳模型权重；**容器重建会丢失 agent 和缓存，需要重新接入、重新下载**。有可用 Docker 时，镜像由 dockerd 保存，不受安装目录的这些镜像文件名限制。

### 加速卡设备权限（非 root 安装）

Linux 上以非 root 用户运行 agent 时，使用 runveil 需要该用户能读写对应厂商的加速卡设备。关闭 systemd 后，nohup 以安装用户运行；该用户即使有免密 sudo，也不等于 agent 以 root 运行。

预检查的 `Accelerator device access` 告警时，请管理员按报告列出的设备组和用户执行 `sudo usermod -aG <组> <用户>`，重新登录后生效。root 运行的 agent 会为工作负载附加设备所属组，无需这一步。

该检查不阻止安装；Docker 以 root 打开设备，不受此用户权限限制。但 NVIDIA 节点的 Docker 缺少 NVIDIA Container Toolkit 时仍可能改用 runveil，见[排障](troubleshooting.md)。

## 一台机器插了多个厂商的卡

一个节点同时只管理一种厂商的卡。自动选择顺序是昇腾、海光、PPU、NVIDIA；主机确有多个厂商的卡时，节点详情显示**加速卡**选择项，直通给虚拟机的卡不计入。

1. 先停止或迁走节点上的实例；仍有未停止实例时不允许切换。
2. 打开节点详情的**加速卡**，选择需要使用的厂商。**自动**选项会显示当前厂商，其他未纳管的卡会有提示。
3. 等待 **正在切换到 …** 提示消失、节点恢复，核对卡的型号、数量和运行时。切换会重启 agent，原厂商的卡不再由该节点管理。

选择会在重启、升级和带外重装后保留。新厂商不受当前容器运行时支持时，自动模式可能改用 runveil，按页面提示检查。

## 重复接入同一台主机

先确定是更新原节点，还是在同一主机上增加另一个节点：

- **更新原节点**：沿用原 Token、安装目录和 state 目录。Linux systemd 安装使用同一个 `gpuworks-agent` 服务，换用其他节点的 Token 会替换原 agent，使原节点离线。
- **新增独立节点**：Linux 上选择不同安装目录并关闭**通过 systemd 启动**（命令行使用 `--no-systemd`），使用独立 state 目录和 Token。其他目录的 agent 与已有 systemd 服务保持运行。SSH 向导可记录自定义目录，便于之后恢复。

预检查中的 `Existing agent` 和 `Existing node` 会提示已有 agent 或同地址节点。SSH 安装在需要替换时要求确认；nohup 模式只确认同一安装目录内的冲突。**手工安装命令和离线包不会等待确认**，替换另一个 server 的 agent 时只输出 `WARNING`，执行前务必核对。

替换后另一个 server 的节点会离线，其带外恢复会报 `foreign_agent`，不会自动抢回。处理方式见[排障](troubleshooting.md)。

## 节点与 server 网络不通

预检查从两个方向检查 server 与节点之间能不能连：

| 检查项 | 方向 | 检查内容 |
|---|---|---|
| Server reachability | 节点 → server | Agent 发起连接时，在节点请求 `server_url` 的 `/healthz`；失败表示节点访问不到这个地址 |
| Server to agent | server → 节点 | 按 server 实际会拨的地址发起 TCP 连接，按下文判断结果 |
| Connectivity | 结论 | 选定方式走不通时，另一方向能通则提示改用它；两个方向都不通则警告，并指向本节 |

**核对 Server to agent 的地址。** 计算节点接入地址自带的端口优先；未带端口时，使用 Server 发起连接的 `--listen` 端口，默认 `18800`。

按探测结果处理：

- **连接成功或被拒绝**：安装前 agent 尚未监听，“连接被拒绝”也算通过，表示数据包已到达节点并返回。server 一侧存在透明代理时，任意 TCP 连接都可能“成功”，因此通过也可能是误报。
- **超时**：检查防火墙、安全组和路由。Server 发起连接时，这是**错误**，详情会提示为 server 放行入站 TCP 端口 `<端口>`。
- **Agent 发起连接时出现此项**：只有节点访问不到 server 时才显示 `Server to agent`，结果作为**警告**，用于判断能否改用另一方向。

两个方向都不通时 agent 装上也连不上，常见于云上没有公网 IP 的实例（例如阿里云 VPC 里没有绑定 EIP、也没有 NAT 网关的 ECS）。按 server 在哪里选一种办法：

| server 所在位置 | 办法 |
|---|---|
| 公网（或有公网入口） | 让节点能出公网：给实例绑定 EIP，或在 VPC 里配置 NAT 网关（SNAT），然后用 server 的公网地址作为 `server_url` |
| 与节点在同一 VPC | 直接用 server 的私网地址作为 `server_url` |
| 其他私有网络（机房、另一个 VPC） | 打通两边网络：VPC 对等连接、云企业网（CEN）或 VPN 网关，然后用打通后可达的地址 |
| 任意位置，不想改网络 | 在节点所在 VPC 里放一台能同时访问节点和 server 的机器做反代（例如 Nginx，配置见[生产环境部署](deploy-production.md#反代配置要点控制台)），`server_url` 填它的私网地址 |

节点能访问 server 但 server 访问不到节点（节点在 NAT 后面）时，用 Agent 发起连接即可，不需要处理。

不能出公网的节点装好 agent 后，仍然不能从公网下载镜像和模型，导入办法见[离线环境部署：节点不能出公网](deploy-offline.md#节点不能出公网)。

## 升级

先升级 server，再更新 agent；节点升级的目标版本来自当前 server。升级会短暂中断该节点的连接与在途请求。多机推理或 PD 分离节点应逐个升级，每次等待节点恢复在线。

- **控制台升级**：在节点列表勾选节点，点击**批量升级 Agent**，预览所选节点并确认后查看逐台进度；也可在节点详情点击**升级 Agent**。等待正式重连成功，再核对节点在线且 **Agent 版本**与 server 一致。新 agent 可经现有连接接收升级包，较早的 agent 仍需访问 server 的下载地址。
- **重新运行安装脚本或离线包**：先保留旧二进制，再沿用原 Token、连接方式、安装和 state 目录执行安装；完成后核对在线状态和版本。这会重写配置，没有自升级的自动回滚。

没有常驻 agent 的手工运行环境，也可使用 [`gpuworks-agent upgrade`](../reference/cli.md#gpuworks-agent-upgrade)。它会进入前台运行，不会重启原服务，不适用于没有 server 地址的 Server 发起连接节点。

新进程注册前后的回滚边界、失败处理和模型调用验证见[升级与版本兼容](upgrade-and-compatibility.md#升级-agent)。

## 维护节点：停止调度与驱逐

升级驱动、换卡或下架一台节点前，在节点列表该节点的**更多 → 调度与驱逐**里操作：

- **停止调度**：不再往这台节点启动新副本，已有副本照常服务。适合短时维护、观察。
- **驱逐**：停止调度，并把这台节点上的副本逐个迁到别的节点——每个部署一次迁一个，先在别处起好替代副本，
  替代副本运行后原副本才退役，服务副本数不低于驱逐前。单机副本由候选池补位；多机与 PD 的副本也会迁：
  替代副本选同计算网络、同 GPU 架构、卡空闲的节点，运行后放置才改写过去，没有节点可去时留在原处等待。
  弹窗列出节点上还剩哪些副本、驱逐会怎么处理它们，每 5 秒刷新。 若仍在等待，弹窗显示最近一次调度反馈及其他节点上最近的失败尝试；这些反馈带时间，并不保证下一次尝试仍会失败。可点“停止驱逐”终止后续迁移并保持节点停止调度，已经开始的操作可能继续完成。平台不自动恢复调度或强制撤下副本。
- **强制驱逐**：钉在这台节点上的单机部署不会被驱逐迁走；需要立即腾空节点时点“强制驱逐”，
  不等替代，全部立即撤下（不计入重试次数），能放到别处的在别处重建，指定了这台节点的等它恢复调度。也可以先在部署详情里
  “编辑”节点条件，让钉住的副本正常迁走。
- **恢复调度**：维护完成后恢复，等待中的副本立即重试。

节点意外下线时，离线超过部署的重调度等待时间（默认 10 分钟）后，副本会自动换到别的节点，不消耗重试次数，见[节点失联重调度](node-failover.md)；等待期间服务能力下降。计划内的维护用驱逐。

## 卸载

手工卸载前，先运行同一命令并加 `--dry-run --json` 查看详细清单。默认要求先处理活动负载或关键未知项，确认后会再次检查；非交互执行需要 `--yes`。明确仅卸载 agent、保留负载时才使用 `--keep-resources`，它不会替你释放 GPU 或清理模型。参数见 [agent 卸载参考](../reference/cli.md#gpuworks-agent-uninstall)。

1. 先停止或迁走节点上的部署实例。
2. 在节点列表选择**更多 → 删除**。普通删除通过已保存的 SSH 凭据卸载对应 agent，确认成功后才删除管理记录；同机其他节点不受影响。
3. 确认节点已从列表移除。普通删除需要已保存的 SSH 凭据；未配置时会保留节点并提示配置 SSH 后重试。手动接入、不支持 SSH 的节点，建议先在节点上手动卸载 agent，再勾选**强制移除：仅删除管理记录**。SSH 连接失败或卸载结果无法确认时，也会保留节点和凭据；可修复 SSH 后重试，或确认手动卸载完成后强制移除记录。

无法联系节点时，可以明确勾选**强制移除：仅删除管理记录**。这会跳过远程卸载，agent 可能仍在运行，
恢复节点访问后需手动卸载。强制移除也不能删除仍有实例的节点。节点上的旧版 agent 若无法停止
nohup 进程，普通删除会失败；先升级 agent 或手动卸载确认后，再强制移除记录。

也可以在节点的**实际安装目录**手工卸载。Linux 命令中的占位符必须替换为该节点原安装命令或启动配置中的 `--state` 目录；未单独设置时与安装目录相同。同机多个 agent 时先核对归属，避免停错节点。以普通用户运行、无需管理系统服务的安装去掉 `sudo`：

```bash
sudo ./gpuworks-agent uninstall --state '<该节点的实际 state 目录>'
```

Linux 命令停止对应 systemd 服务或 nohup 进程，确认退出后删除节点身份、连接配置和 PID 文件；失败时返回非零状态。Mac 使用 `./gpuworks-agent uninstall` 移除 launchd 任务，LaunchDaemon 需加 `sudo`，state 目录从任务读取。

**二进制、模型、日志和 state 目录保留。** 手工卸载成功后，回控制台勾选**强制移除：仅删除管理记录**，完成节点移除。需要彻底清理数据时，先确认没有实例或模型仍在使用，再由管理员删除相应目录。
