# 配置节点网络

为有多张网卡的节点指定存储同步、参数（多机推理与 PD 的 KV 传输）和服务流量使用的网络，再用内部测试检查节点间连通性与带宽。创建网络只声明已有网络的用途，不会配置交换机、网卡地址或布线。

开始前，用管理员账户登录，确认相关节点已[接入](connect-nodes.md)并上报网卡清单。按要使用的类型准备：

- **主机以太网**：节点在目标网络上已有可用地址。
- **主机 RDMA**：有 ACTIVE 的 InfiniBand 或 RoCE 端口；RoCE 对应网卡还需 IPv4 地址。带宽测试需要可运行的 `ib_write_bw`，工具条件见[内部测试](#内部测试)。
- **加速器 RDMA**：昇腾卡的网口已配置地址且链路 UP，agent 能通过 `hccn_tool` 读取。
- **加速器 HCCS**：A3/910C 节点的灵衢 HCCS/vNIC 已配置，agent 能通过 `hccn_tool -vnic` 和 `-hccs_ping` 读取与验证。

多机推理和 PD 的部署步骤分别见[多机推理](multi-node-inference.md)与 [PD 分离部署](pd-disaggregation.md)。网络对象的设计与推断规则见 [ADR 0030](../adr/0030-network-objects.md) 和 [ADR 0027](../adr/0027-rdma-network-inference.md)。

## 监听地址与「别人怎么连过来」

server 自己不存、也不推断对外地址（见 [ADR 0025](../adr/0025-server-holds-no-external-address.md)）。
设置 → 通用里的「监听地址」卡片（即 `server.yaml` 的 `listen.*`，修改方法见[配置参考](../reference/configuration.md#在控制台修改监听地址)）只决定 server 在**本机**绑定哪些 `IP:端口`；别人用域名、反向代理还是 NAT 转发连过来，由调用方自己选择。
UI 里需要填 server 地址的地方都用浏览器当前访问的地址预填，可以改成域名或反代地址；API 对应字段 `server_url` 必须显式传入。
改 `listen.agent` 会影响**已装**的 agent：它们只拨打安装命令里那个地址，该地址不再转发到新监听地址时就会离线，直到转发修好或重装。

「算力资源 → 网络」页顶部的「网络拓扑与配置」卡片用一张简单拓扑和一张复杂拓扑，把每一项配置画在图上
并配一张编号对照表：在哪里设置、起什么作用、不决定什么；把鼠标移到编号或表格行上会互相高亮，
不熟悉这套地址概念时建议先看这张图。

## 网络

1. 打开**算力资源 → 网络**，点**新建网络**，填写名称，选择角色与类型，并按下列说明设置选择器。一个网络可承担多个角色；加速器 RDMA 和加速器 HCCS 只能承担参数角色。
2. 点**保存**，进入新网络的详情页。按[加载到节点或标签](#加载到节点或标签)加载目标节点。
3. 在详情的节点列表核对实际 IP、网卡；RDMA 网络还要核对 bootstrap 和 HCA。橙色叹号表示有未生效或不可用的配置，先查看原因并修正。
4. 需要验证节点间路径时，按[内部测试](#内部测试)发起测试。网络声明保存成功不代表实际链路已通；运行中的实例仍使用启动时的网络，下次启动才应用变更。

创建时的字段含义：

- **角色**（可多选）：`存储同步`（节点间同步模型和镜像）、`参数`（多机推理的 NCCL/Gloo 与 PD 分离的 KV 传输）、`服务`（网关访问推理实例）。三个都选就是 all in one。
- **类型**：`主机以太网`（`host_ethernet`）、`主机 RDMA`（`host_rdma`）、`加速器 RDMA`（`accelerator_rdma`）或 `加速器 HCCS`（`accelerator_hccs`）。主机 RDMA 同时涵盖 InfiniBand 和 RoCE，每个节点是哪一种由其 RDMA 端口的链路层自动识别，显示在节点行上；同一网络内识别出不同链路层时给出橙色叹号。加速器 RDMA 是加速卡自带的 RoCE 口；加速器 HCCS 是 A3/910C 的灵衢 HCCS/HIXL 链路，见[下文](#加速器-hccs-网络a3910c-灵衢链路)。类型决定参数网络的 NCCL/UCX/HCCL 配置和设备注入。只有同一个网络对象上的节点被视为互通。
- **默认选择器**（只有主机以太网需要）：填"默认网段"，流量走地址落在其中的网卡；网卡名（支持 `*`、`?`、`[...]` 通配）只在网段区分不开时需要。
- 主机 RDMA、加速器 RDMA 与加速器 HCCS 网络**不需要填写任何选择器**，见下三节；"高级"里只有一个可选的 bootstrap 网段。

### RDMA 网络：bootstrap 与 HCA 自动推断

RDMA 网络上每个节点用两样东西：

- **HCA**（rail）：承载数据的 RDMA 端口，如 `mlx5_0:1`。RoCE 端口的 **HCA IP** 是它所在网卡的 IPv4 地址，RoCE v2 靠它建立连接；InfiniBand 端口不需要 IP，显示"—"。
- **bootstrap IP**：握手用的 TCP 地址（NCCL 带外通道、Gloo、vLLM master 地址、ib_write_bw 交换连接参数），数据不经过它。它可以不在 RDMA 网卡上。

加载节点后，按 agent 上报的网卡清单为每个节点推断：

| | 规则 |
|---|---|
| HCA | 取状态为 ACTIVE 的端口；节点上有 InfiniBand 端口时只取 InfiniBand，否则取 RoCE；RoCE 端口要求所在网卡有 IPv4 地址；只保留速率最高的一组（RoCE 按网卡速率），例如排除 1G 管理口 |
| bootstrap | 依次取：节点上指定的 bootstrap；网络填了 bootstrap 网段时，地址落在其中的网卡（没有命中就留空并告警，不回退）；第一条 HCA 所在网卡的地址；没有 IPoIB 的 InfiniBand 用管理网地址 |

网络详情的节点列表按节点列出 bootstrap IP 和成组的 HCA 与 HCA IP，旁边标"自动"或"手动"：

- 每条 HCA 旁的 ✕ 移除它，默认从网络上**所有**用它的节点移除（各节点的 HCA 要一一配对），可勾选"只从本节点移除"；「添加 HCA」从该节点上报的端口里选，不可用的端口写明原因（未激活、网卡没有 IPv4 地址）。第一次增删后，该节点的 HCA 固定为当时的列表（"手动"），不再随网卡清单变化；「恢复自动」回到推断。节点最后一条 HCA 不能移除，不再使用时请卸载该节点。
- bootstrap 的「修改」从该节点带地址的网卡里选，「恢复自动」清除。
- 这些修改只写在节点的加载项上；经标签加载的节点第一次修改时会为它生成一个节点加载项。

推断出的节点会带上这些提示（橙色叹号）：没有可用的 RDMA 端口、没有 bootstrap 地址、手动指定的 HCA 不可用、各节点 HCA 数量不一致。

### 加速器 RDMA 网络：加速卡自带的网口

昇腾 910 每张卡自带一个 RoCE 口，主机内核看不到它（不在网卡清单的网卡和 RDMA 端口里），只能用 `hccn_tool` 访问。昇腾跨机的集合通信（HCCL）只走这些口：没有开关能让它改走主机网卡，也不会自动回退，所以**昇腾多机部署必须使用加速器 RDMA 网络**，否则被拒绝（`COMPUTE_NETWORK_ACCELERATOR_REQUIRED`）。

加速器 RDMA 网络上每个节点同样用两样东西：

- **rail**：加速卡，写作 `npu3`（3 号卡）。地址、链路状态和速率由 agent 用 `hccn_tool` 读取，每分钟刷新一次；节点详情「网卡清单」的「加速卡网口」表列出全部。
- **bootstrap IP**：握手用的主机地址（HCCL 建通信域、Gloo、vLLM master 地址）。主机进程无法绑定加速卡网口的地址，所以它一定是主机网卡上的地址。

| | 规则 |
|---|---|
| rail | 链路 UP 且配了 IPv4 地址的加速卡，按卡号排列 |
| bootstrap | 依次取：节点上指定的 bootstrap；网络填了 bootstrap 网段时，地址落在其中的主机网卡；管理网地址 |

增删 rail、修改 bootstrap、"自动 / 手动"的含义与主机 RDMA 网络相同；「添加 HCA」列出的是该节点的加速卡。

它**只能承担参数角色**：存储同步和服务都是主机进程，绑不了加速卡网口的地址。表单里这两个角色置灰，API 返回 `NETWORK_TYPE_ROLE_INVALID`。

网络只声明"这些节点的加速卡网口连在一起"，不决定实例用哪几张卡：实例用调度选中的卡，哪两张卡之间能通取决于布线。两台机器按卡号直连时只有同号卡之间能通，而这从地址上看不出来（两台的卡可以在同一个网段里）。

### 加速器 HCCS 网络：A3/910C 灵衢链路

A3/910C 的灵衢 HCCS 是独立于加速器 RoCE 的 HIXL 传输路径。节点详情中的 vNIC 地址可用 `hccn_tool -vnic -g` 查看，节点间的卡级连通性用 `hccn_tool -i <卡号> -hccs_ping -g address <对端地址>` 双向验证。HCCS 网络同样按加速卡作为 rail、按主机地址作为 bootstrap，只能承担参数角色。

选择 HCCS 后，vLLM-Ascend/Mooncake 会自动使用 `hccs:device` 协议，并注入 A3 所需的 HIXL/Fabric Memory 环境；不要把 HCCS 地址改写进 `/etc/hccn.conf`，该文件仍保留 RoCE/HCCN 地址供驱动和容器使用。

### 加载到节点或标签

在网络详情点**加载**，选择多个节点，或改选节点标签并填写 `key=value`，点**保存**。核对加载结果与节点列表；个别节点失败时只处理失败项，不必重做已成功的项。

网络可以加载给任意个节点和节点标签。每个节点每个角色最终只用一个网络：

1. 直接加载到节点的优先于经标签加载的。
2. 同一优先级命中多个同角色网络时，先加载的生效。节点详情页和网络详情页的节点列表会在该节点旁显示橙色叹号，悬停可以看到没有生效的网络。

「加载」可以一次选多个节点；个别节点失败（例如节点已删除）不影响其他节点，结果里逐个列出，已经加载过的节点算成功。

主机以太网加载到节点时可以覆盖默认选择器：指定网卡或 IP。主机 RDMA、加速器 RDMA 与加速器 HCCS 网络在节点上可以指定 bootstrap 网卡或 IP（见上面各节），rail 在节点列表里增删。覆盖值会用 agent 上报的网卡清单校验，清单里没有时同样显示橙色叹号。节点离线时也能保存。

节点详情页的「已加载网络」列出这个节点每个角色实际用的网络、网卡、IP 和 HCA；「网卡清单」是 agent 从 sysfs 读取的网卡、地址、速率和 RDMA 端口，以及昇腾节点上用 `hccn_tool` 读取的加速卡网口。只上报物理网卡和带地址的虚拟网卡（网桥、bond、VLAN）。

### 管理网

每个节点都在内置的**管理网**上：节点连接 server 所用的本机地址（经 127.0.0.1 或 HTTP 代理连接时，改用默认路由所在网卡的地址），由 agent 自动上报。管理网没有对应的网络对象，不能删除、修改或加载；它排在网络列表第一行。某个角色没有加载任何网络时，由管理网承担。每个节点可以分别关闭「管理网可承担存储同步 / 参数同步 / 服务」，默认全部开启，只对新实例生效（需要管理员）：

- 管理网详情页的节点表每个角色一列开关，可逐个切换；角色开着但已由独立网络承担时，开关旁注明「由独立网络承担」。
- 同一页可按名称、地址搜索，按节点标签筛选，勾选节点（或「选中筛选结果」）后批量设置：每个角色选「保持不变 / 允许 / 禁止」，只修改选中的角色，全部节点一起成功或一起失败。
- 节点详情「网络」页的「管理网」卡片也能切换本节点的角色。管理网承担服务时走 agent 隧道，不启用服务网络转发。

「管理网」卡片还显示 server 看到的连接来源；它与管理网地址不同时标「经 NAT 接入」，只作展示。

### 各角色怎么生效

**存储同步：确认两端使用的路径**

节点间复制模型和镜像按节点对选网络：两端共同的存储同步网络优先；没有共同网络时，只有两端都允许管理网承担存储同步才走管理网。自动复制只发生在同一[同步组](configure-pull-settings.md#同步组)内，手动同步不受同步组限制。

接收端只在所选网络的 IP 上监听，发送端从本端在该网络的 IP 发起。同步源候选中，与目标同属一个存储同步网络的节点排在最前并被推荐。

两端没有可用的共同路径时，不做节点间直连：自动复制跳过该源，副本改为自己拉取镜像或下载模型；手动指定该源时报 `NO_STORAGE_PATH`。

直连所有候选地址均无法建立 TCP 连接时，两端都允许管理网承担**存储同步**且新版 agent 的独立数据通道可用，可经 server 中继模型或镜像。新版 agent 主动连接与 server 经 SSH 纳管两种方式，中继都走与控制连接分离的数据连接；无需两端私网地址互通或逐个映射随机端口。旧 agent 或只建立单通道的节点只能直连，须升级并启用独立数据通道才能中继；数据通道不可用时不会改用控制连接传文件。任一端关闭管理网存储同步权限就禁止中继；要只走直连，保留共同的专用存储同步网络并关闭该权限。

中继仅在传输开始前作为 TCP 建连失败的兜底；TLS、令牌或传输校验失败不会切换。连接断开后整任务从头重试，不支持续传。中继沿用端到端加密和限速，并限制为每节点一个、server 进程两个并发任务、所有中继共用 64 MiB/s 的进程总预算，更低的用户或同步组限速仍生效。镜像的**测试传输连接**显示本次直连或中继路径，模型实际路径见 server 同步日志。详见[节点间同步](peer-sync-models.md)。

下方 TCP 内部测试始终检查所选地址之间的真实直连；中继成功不会改变其失败结果。文件中继不提供 NCCL/Gloo 或 RDMA 互通，参数网络与服务网络的要求也不因中继而改变。

**参数：核对整组实际使用的网络**

多机部署的所有节点共用同一个参数网络时使用它。没有全体节点共用的参数网络时（全部未加载、仅部分加载，或各节点位于不同参数网络）：

- 所有节点都允许管理网承担参数同步，整组回退到管理网，评估给出 `COMPUTE_NETWORK_FALLBACK` 提醒。
- 有节点不允许管理网承担参数同步，部署被拒绝（`COMPUTE_NETWORK_NONE` / `COMPUTE_NETWORK_MIXED` / `COMPUTE_NETWORK_MISMATCH`）。想避免回退，可在这些节点上关闭管理网可承担参数同步。

在命令预览和实例详情核对实际通信地址、设备。各 rank 的 `VLLM_HOST_IP` 使用自身在所选网络上的 IP，rank 0 地址用作 master；主机网络按所选网卡配置 NCCL/Gloo。多机实例详情的**参数网络**显示该 rank 启动时实际用的网络、网卡和 IP，走管理网时标明回退。

不同类型的行为与限制如下：

- **主机以太网**：设置 `NCCL_IB_DISABLE=1`，使用 TCP。
- **主机 RDMA**：设置 `NCCL_NET=IB`，给 NCCL 提供全部 HCA、给 UCX 提供第一张 HCA，并向容器暴露 `/dev/infiniband` 和所需锁定内存权限。容器看不到 verbs 设备时启动失败，不会静默退回 TCP；模板或用户设置的同名环境变量仍优先。runveil（运行时标识 `udocker`）无法向容器暴露 RDMA 设备，不能使用此类参数网络（`COMPUTE_NETWORK_RUNTIME`）。
- **加速器 RDMA**：为 HCCL 提供 bootstrap IP 和网卡，并只读挂载主机 `/etc/hccn.conf`；使用加速卡网口，不注入 `/dev/infiniband`。昇腾多机部署必须共用此类网络（`COMPUTE_NETWORK_ACCELERATOR_REQUIRED`），每个节点至少有一张可用的卡（`COMPUTE_NETWORK_NO_CARDS`）。
- **加速器 HCCS**：为 A3/910C 的 Mooncake/HIXL PD 路径选择 `hccs:device`，并自动启用 HCCS 所需的初始化和 Fabric Memory 参数；仍只读挂载 `/etc/hccn.conf`，但不把 RoCE 端口当作实际 KV 传输路径。

PD 分离还按模式检查 KV 传输网络：

- `vllm-ascend-mooncake` 跨机时必须使用加速器 RDMA 或加速器 HCCS 网络（`PD_NETWORK_ACCELERATOR_REQUIRED`）。
- 走 UCX 或 Mooncake 传输引擎的模式（`vllm-nixl`、`sglang-nixl`、`vllm-mooncake`）不能使用加速器 RDMA 网络（`PD_NETWORK_HOST_REQUIRED`）。
  `vllm-mooncake` 在主机 RDMA 网络上用 Mooncake 的 `rdma` 协议，其他网络用 `tcp`。
- 可休眠的 PD 部署不能让 KV 走主机 RDMA 网络（`PD_SLEEP_RDMA_UNSUPPORTED`），创建时会拒绝；创建后再挂上 RDMA 网络，部署会停在无法调度并给出同一原因。普通多机部署经 RDMA 做集合通信不受此限制，见 [sleep / wake](sleep-wake.md) 的限制。

具体变量与容器参数见[部署启动参数来源](../reference/deployment-launch-sources.md#拓扑)。

**服务：验证 server 到节点的转发端口**

服务网络的防火墙须放行 server 到节点服务 IP 的 `19443/tcp`。agent 在该端口提供 TLS 转发，网关使用每个实例的令牌连接，再转到实例的回环端口。调用方仍带 API key 走网关，不直接访问这个转发端口。

节点有服务网络时，**只经服务网络访问，不回退 agent 隧道**：

- 实例调度到节点后、启动容器前，server 会连接该端口并完成 TLS 握手；不通时实例失败并写明原因。
- 已运行的实例遇到服务网络不通时，请求直接失败。在节点详情的**服务网络转发**查看地址与状态，不可达时悬停查看原因。

server 的拨号不绑定源地址，按本机路由表选择；同网段有服务网络网卡时通常使用它。

没有服务网络时，允许管理网承担服务的节点走 agent 隧道；关闭此权限且没有服务网络时，调度不会把实例放到该节点（`serving_unavailable`）。

网络、加载关系或节点标签变化后，server 会给在线节点重新下发配置。运行中的实例不受影响，下次启动才用新网络。

## 节点代理与下载地址

节点出网用的代理（`http_proxy` / `https_proxy` / `no_proxy`）和模型、镜像的下载地址（镜像站、内网代理、禁止回源）不在这里配，它们与上面的存储同步 / 参数 / 服务网络是不同的东西：在设置 → 镜像与模型拉取里按节点标签配置，分别是「代理」和「来源规则」。节点详情有只读的「拉取代理」卡片，显示这台节点实际用的代理和 dockerd 状态。规则、代理、示例与排障见[配置镜像与模型拉取](configure-pull-settings.md)，docker 节点的 dockerd 代理见[其中的 dockerd 一节](configure-pull-settings.md#dockerd)。

agent 每 10 秒采集各网卡与 RDMA 端口的收发速率、错误与拥塞，以及按角色的节点流量。指标名称、标签和口径见[网络监控指标](../reference/network-metrics.md)。

- 节点详情「网络」页的网卡清单和 RDMA 端口表显示最近两分钟的实时速率。
- 网络详情页（含管理网）的「监控」标签页按节点画出该网络的流量、错误与拥塞，可选 15 分钟到 24 小时。

## 内部测试

存储同步网络、参数网络和管理网的详情页有**内部测试**标签页。先确定要验证的路径，再准备相应工具与范围。

### 选择测试方式与范围

| 目的 | 测试方式 | 能确认什么 |
|---|---|---|
| 验证主机地址间连通性、RTT 或 TCP 吞吐 | TCP | 以太网的所选地址；RDMA 网络的 bootstrap 地址 |
| 检查主机 RDMA 各 HCA 的带宽 | RDMA 带宽（ib_write_bw） | 宿主机的 RDMA 路径，不等同于容器内 NCCL 验证 |
| 巡检昇腾同号卡是否可达 | 卡连通性 · 同号卡 | 只测同号卡对 |
| 确定昇腾不同卡号之间的实际布线 | 卡连通性 · 全卡矩阵 | 所选节点间的全部卡对 |

管理网只提供 TCP 测试，覆盖所有已上报管理网地址的节点，即使独立网络已接管它的全部角色。

测试哪些节点对，可选：

- **全互测**：覆盖所有节点对；TCP 和 RDMA 带宽按有序节点对测试，N 个节点共 N×(N−1) 对、分 N−1 轮。一次最多 128 个节点。
- **环形**：节点按名称排成一圈，各测下一个，最后一个测第一个，共 N 对。TCP 和 RDMA 带宽一轮完成，每个节点恰好发、收各一次。超过 16 个节点时默认选环形，一次最多 1024 个节点。

环形能发现单个节点或单条 HCA 的问题，但发现不了只在不相邻节点间出现的不通，例如 fabric 分成两半而相邻节点恰好在同一半。加速卡测试的配对和耗时另见下文。

### 准备 TCP 或主机 RDMA 测试

**TCP** 从源节点在该网络上的地址，连接目标节点对应网络地址上的临时端口，测认证握手 RTT；可选再测几秒吞吐。每轮每个节点只收发各一路。在 RDMA 网络上，TCP 只走 bootstrap 网卡。

**RDMA 带宽（ib_write_bw）** 先检查 HCA 和工具：

- 每对节点在目标 HCA 上起服务端，再从源 HCA 连接，各 HCA 并行运行，带宽为各 HCA 之和。两端 HCA IP 同子网时优先配对（包括点对点 /30、/31），其余按顺序配对；多出来的 HCA 以“对端没有可配对的 HCA”失败。握手走目标节点的 bootstrap 地址。
- RoCE 使用 IPv4 的 RoCE v2 GID，与 NCCL 2.21 及以上的默认选择一致。RoCE 网卡没有 IPv4 地址时直接报告失败，不交给工具自选 GID。
- 工具优先使用宿主机 `PATH` 中的 `ib_write_bw`，其次用 agent 内置版本。内置版本动态链接宿主机的 `libibverbs`、`librdmacm`，安装 rdma-core 或 MLNX_OFED 这类用户态库后即可运行。两者都不可运行时，发起前会列出对应节点，测试也会以“没有可运行的 ib_write_bw，请安装 perftest”失败；安装 perftest 时包管理器会一并安装用户态库。

TCP 与 RDMA 带宽在 agent 宿主机执行，覆盖存储同步和主机以太参数网络的真实路径，不验证容器内推理 rank 的 NCCL 路径。自定义镜像的 NCCL 版本或 `NCCL_IB_GID_INDEX` 可能使容器选择不同 GID；RoCE 测试通过而容器通信失败时，按镜像版本核对 [NCCL 的 GID 与 RoCE 配置](https://docs.nvidia.com/deeplearning/nccl/user-guide/docs/env.html#nccl-ib-gid-index)，不要把 GID index 0 固定视为某一种 RoCE 版本。

### 准备加速器 RDMA 测试

- **TCP** 只验证握手用的 bootstrap 地址，不经过加速卡网口。
- **卡连通性 · 同号卡**（`card_ping`，默认）由两个节点的同号卡互相 ping，例如 `npu3` 对 `npu3`，适合日常巡检。
- **卡连通性 · 全卡矩阵**（`card_matrix`）由一个节点的每张卡 ping 另一个节点的每张卡，建网时用它确认布线。不同卡号是否相通不能仅从地址判断。

agent 在宿主机用 `hccn_tool -i <卡号> -ping`（加速器 RDMA）或 `hccn_tool -i <卡号> -hccs_ping`（加速器 HCCS）测可达性，不测带宽。有回包即可证明双向可达，因此每两个节点只测一次：全互测共 N×(N−1)÷2 对，环形 N 对。

测试按轮次错开节点和卡，每张卡同一时间只发一次 ping；不通时一轮最长等待 3 秒。预计耗时按轮数计算，不逐个累加全部探测。可按下表选择范围：

| 24 个节点 × 8 张卡 | 探测数 | 轮数 | 最长耗时 |
|---|---|---|---|
| 环形 + 同号卡 | 192 | 1 | 3 秒 |
| 环形 + 全卡矩阵 | 1536 | 8 | 24 秒 |
| 全互测 + 同号卡 | 2208 | 12 | 36 秒 |
| 全互测 + 全卡矩阵 | 17664 | 96 | 4.8 分钟 |

表单会显示节点数、探测数、轮数和预计最长耗时。轮数 × 3 秒超过 10 分钟的组合不能发起（`NETWORK_TEST_TOO_LONG`），需缩小范围或改用环形、同号卡。

### 开始测试

1. 选择测试方式、**测试范围**（网络上全部节点、指定节点或按标签筛选）和**测试哪些节点对**（全互测或环形）。至少需要两个节点；测 TCP 吞吐时勾选**测量吞吐**，设置每对测试秒数。
2. 检查发起前的地址、HCA 和工具提示：没有地址（RDMA 为 bootstrap）或没有可用 HCA 的节点会列出。卡测试还需核对预计耗时。修正影响本次测试的配置后，点击**开始测试**。
3. 等待结果，先看问题汇总，再打开失败节点对查看详情。按下面的结果说明修复布线、地址或工具；重新运行相同范围，确认问题消失。

每个网络保留最近 10 次结果；server 重启时，正在进行的测试会标为中断。

### 查看 TCP 与 RDMA 带宽结果

**问题汇总**按节点、HCA 和原因合并失败，写明影响几对。确实不应使用的 HCA 可直接点击**移除 HCA**，重新测试后生效。

下方全互测显示节点矩阵，环形显示节点对列表。每对分为**通过 / 部分通过（部分 HCA 失败）/ 失败**；点击或按回车查看源、目标地址和 RTT，RDMA 测试还列出每条 HCA 的源与目标、各自 IP 和结果。

### 查看加速卡连通性结果

全卡矩阵用于判断部署时如何选卡。只测同号卡时，“同号卡全通”只能证明同号卡可达，不能推断其他卡号组合。结果只代表测试时刻，布线或链路变化后需重测。

| 形状 | 含义 | 结论 |
|---|---|---|
| 全互通 | 每对卡都通 | 任意卡号组合可用 |
| 仅同号卡 | 只有同号卡之间通（按卡号直连，或按卡号分平面） | 两端必须选相同卡号 |
| 部分可达 | 其他情况 | 布线不规则，按各节点对的结果选卡 |
| 全不通 | 没有一对卡通 | 检查加速卡网口的链路与地址 |
| 未测 | 节点离线、没有卡，或没有同号卡可测 | 看该节点对的原因 |

节点对状态按形状判定：全互通与仅同号卡均为可部署形态，算**通过**；部分可达算**部分通过**；全不通与未测算**失败**。

多数节点对形状相同时，会给出该形状的结论并点名不同的节点对，便于定位布线或配置问题。节点对总览中，全互测是节点 × 节点的表，环形是列表，每格显示该对的形状。

点击或按回车打开节点对：全卡矩阵显示“源卡 × 目标卡”网格，同号卡显示逐对列表；悬停可看两端地址、RTT 或失败原因。只测一个节点对时直接显示这张网格。
