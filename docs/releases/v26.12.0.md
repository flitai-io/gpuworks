# v26.12.0

发布日期：2026-11-26 · 发布线：26.12 · 提交：`92ffae740`

26.12 发布线的首个版本。相比 v26.11.4，这一版可以把 Kubernetes 与 Slurm 集群整体接入，新增 AMD 与昆仑芯两类加速卡，
加入请求优先级，并让 `/v1` 推理网关默认要求 API key。本版包含数据库迁移，升级前请先读下面的升级须知。

## 升级须知

- **本版有数据库迁移，升级后不能直接换回 26.11 的程序**：迁移在新版 server 首次启动时执行，只向前、不支持反向迁移。升级会自动备份主数据库、配置、`master.key` 和旧二进制，
  手工替换二进制前请自行备份数据目录。需要回到 26.11 时，按[升级与版本兼容](../how-to/upgrade-and-compatibility.md#回滚)从升级前的备份恢复。
  备份不含统计库 `stats.db`，而本版升级了它的结构：恢复后 26.11 的 server 会以 `stats.db was written by a newer release` 拒绝启动，需在停服状态下把数据目录中的 `stats.db`（及 `-wal`、`-shm`）移到别处保留，再启动。
  旧版会新建一个空的统计库：用量分析里的 GPU 利用率与卡时历史、调度分析里 24 小时之前的历史不再显示；用量分析的服务质量会按请求观测库 `ux.db` 仍保留的天数重新填入；按令牌的 token 用量在主数据库里，不受影响。
  升级失败触发的自动回滚同样不处理 `stats.db`：新版只要启动过，恢复的旧版也要先做这一步才能启动。
- **`/v1` 默认要求 API key**：不带 key 的请求返回 401，库里没有任何 key 时也一样。此前删掉了全部 key、靠无 key 访问的安装，升级后需要创建 key，
  或由管理员在**设置 → 安全**打开「接受不带令牌的 /v1 推理请求」（`inference_open_access`）。新装的 server 不再自动创建 `default` 令牌。见 [OpenAI 兼容网关](../reference/openai-gateway.md#认证)。
- **先升级 server，再升级 agent**：经管理节点中继的复制、启动卡死检测等能力需要 agent 也升到本版。
  升级 server 后，**版本与更新**在服务端行下方显示版本不一致的在线节点数量，点击「查看计算节点」到筛选好的节点列表批量升级。
- **旧版安装器装在 `/opt/gpuworks` 的控制面，命令行升级要用 root**（`sudo ./gpuworks upgrade`）：升级会先把该目录改为 root 所有。
  没有 root 权限时命令拒绝执行并给出要运行的命令。迁移后服务账户不能再替换这个目录里的二进制，这类安装的控制台升级显示为不可用（`not_writable`），此后每次升级都用 `sudo /opt/gpuworks/gpuworks upgrade`。见[安装布局](../reference/install-layout.md#控制面装在-agent-共享根目录时)。
- **请求优先级只对新部署默认开启**：升级前创建的部署保持关闭，需要时在编辑里打开，修改这个开关会重建副本。
- **管理员密码规则改为 8–128 个字符**，并拒绝常见口令、整段重复和序列。只在新建或修改密码时检查，已有账户照常登录。
- **凭据文件的权限会被收紧**：启动、安装和升级会把存量敏感文件改为仅所有者可读写（`0600`）。只有 systemd 单元的组是默认凭据组，或旧单元以默认服务账户运行时，才对可信服务组开放（`0660`）；其他自定义账户的安装仍是 `0600`。
- **卡健康码改为大写**：迁移把 `gpus.health_code` 与卡健康记录的原因码从小写改为 UPPER_SNAKE，API 响应里的 `health_code` 随之变化。按旧的小写值匹配的脚本或告警规则需要改。
- **重名的同步组会被改名**：同步组名称现在必须唯一，升级时存量重名的组按 ID 加后缀，组 ID、节点条件和限速不变。
- **用 nightly 构建接入过 Kubernetes 集群的站点，升级 server 后重新应用一次 manifest**（`kubectl apply` 或「应用到集群」）：agent 的 Pod 由此与节点共用默认挂载目录 `/mnt/gpuworks`。
  不重新应用时，挂载点在该目录下的 NFS 存储在这些节点上报「agent 与节点不共用这个目录」，不会挂载。见[接入 Kubernetes 集群](../how-to/connect-kubernetes.md)。

## 新增

### 集群与节点接入

- **接入 Kubernetes 集群**：以 DaemonSet 接入已有的 containerd 集群，一个集群条目可同时覆盖 NVIDIA、昇腾、海光、PPU、AMD 与昆仑芯节点；
  支持整卡部署，NVIDIA、昇腾、PPU 与 AMD 另支持 dGPU（海光与昆仑芯只做整卡），可经 HAMi 与阿里云 ACK 共享 GPU 借卡。见[接入 Kubernetes 集群](../how-to/connect-kubernetes.md)。
- **接入公有云托管 Kubernetes**：阿里云 ACK、DigitalOcean DOKS、Nebius mk8s 已实测。ACK 与 DOKS 的集群还可从云账号接入，在控制台按检查过的计划应用和移除，前提是集群的 API Server 有公网地址；Nebius 用 `kubectl` 应用。
  见[接入公有云托管 Kubernetes](../how-to/connect-managed-kubernetes.md)。
- **接入 Slurm 集群**：在管控节点执行一次接入命令，GPU 计算节点自动装上 agent；卡仍归 Slurm 分配，部署用占位作业借卡。目前只支持 NVIDIA 卡，
  阿里云 E-HPC 集群可在云账号里直接接入。见[接入 Slurm 集群](../how-to/connect-slurm-nodes.md)。
- **DigitalOcean**：新增云账号类型，同步 GPU Droplets 与 DOKS 集群。见[租用云 GPU](../how-to/rent-cloud-gpus.md)。
- **ZStack Cloud**：兼容旧版与过渡版的 Cloud GPU 协议，最低适配 4.8.0。见[接入 ZStack Cloud](../how-to/onboard-zstack-cloud.md)。
- **NAT 后的节点**：两台节点连不通时，模型与镜像的复制可经管理节点中继；中继的限速与超时在 `server.yaml` 的 `peer_relay` 配置，并发数固定。见[在节点之间同步模型和镜像](../how-to/peer-sync-models.md)与[节点间中继的资源限制](../reference/configuration.md#节点间中继的资源限制)。
- **连接证据**：节点长时间连接中或离线时，管理员可在节点详情的「连接证据」点「检查连接」读取只读证据，不需要控制面能 SSH 到节点。
- **「外部平台」页**：云账号以及 Kubernetes、Slurm 集群条目都在「算力资源」下的「外部平台」页添加和管理。
- **文档**：新增[在 Windows WSL2 上用 Docker 运行 GPUWorks](../how-to/wsl2-with-docker.md)。

### 加速卡

- **AMD（ROCm）**：Linux amd64 上的 Docker、nerdctl、runveil 与 Kubernetes 整卡部署，已在 MI325X（gfx942）与 AMD395（gfx1151）上实测单卡 BF16 文本推理，其余组合待逐档验证。多机与 PP 已在两台 MI325X 上实测，vLLM sleep/wake 与 PD（`vllm-nixl`）已在 MI300X 上实测。dGPU 提供用户态硬显存上限（实验特性，不提供算力上限）。内置 `rocm7.2.3-vllm0.30.0-r1` 镜像与 Qwen3 的 gfx942、gfx1151 规格。
- **昆仑芯 P800**：Linux amd64 上的 Docker、nerdctl 与 Kubernetes 整卡部署，平台开放 TP、PP、引擎 DP 与多机 TP，不开放 PD、分区和 sleep。只实测了单卡（生产启动、经网关对话，以及 Kubernetes 节点上的单卡部署）；单机多卡在测试环境被 XRE 初始化错误阻断，跨机未测，多卡与跨机尚未验收。见[昆仑 P800 部署](../how-to/kunlun-p800.md)。
- **NVIDIA 统一内存卡**：在 GB10 之外新识别 RTX Spark 与 Thor；`nvidia-smi` 不报已用显存时，已用量也按宿主机内存池计量。Thor 尚未在硬件上验证。
- **PD 分离扩展到海光与 PPU**：新增 `vllm-mooncake`、`sglang-mooncake`（海光，未验证）、`sglang-ppu-ipc`、`sglang-ppu-mooncake`、`vllm-ppu-mooncake` 模式。见[PD 分离部署](../how-to/pd-disaggregation.md)。

各组合的验证状态见[厂商支持矩阵](../reference/support-matrix.md)。

### 部署与推理

- **请求优先级**：引擎按优先级排队，优先级只由网关按 API 令牌绑定的优先级类和请求头 `X-GPUWorks-Priority-Class` 决定。见[请求优先级](../explanation/request-priority.md)。
- **把部署另存为推理模板**：从运行中的部署导出可直接导入的 YAML 与测试记录。见[把部署另存为推理模板](../how-to/save-deployment-as-template.md)。
- **多机与 PD 部署支持手写启动命令**：在命令预览点「编辑命令文本」，从服务端生成的脚本开始修改。
- **KV 卸载后端**：部署时按引擎选择 KV 卸载后端，vLLM 内置 `native`（默认）与 LMCache 两个。
- **模板能力**：模板可声明受管的可写目录（`dirs`）、让每个 rank 下载并挂载各自的权重子目录、在第二个端口提供引擎指标。
- **System One 决策接口**：网关新增 `/v1/systemone`，提供这个接口的部署也可做健康检查。
- **MinerU**：内置 MinerU2.5 视觉模型模板，配合 MinerU 客户端解析 PDF。见[用 MinerU 连接远程视觉模型](../how-to/use-mineru.md)。
- **内置目录**增至 405 个模型（v26.11.4 为 392 个），新增 SenseNova-U1.6-8B-MoT、昆仑芯 Qwen 规格、Strata GGUF 规格，以及两台与四台 DGX Spark 上的 DeepSeek-V4.1-Flash。

### 镜像、监控与运维

- **镜像导入**：在镜像的「节点分布」里把获取方式选为「从节点本地文件导入…」，可导入该节点上的 tar 归档；也可导入节点已有的 Docker 和 nerdctl 镜像。
- **压测**：结果页新增可交互的请求时间线，可按会话、轮次和尝试查看；新增**单请求超时**，默认 600 秒，可设 10–7200 秒。
- **启动卡死检测**：agent 在容器创建后每分钟观察输出、卡的显存与利用率、容器进程的活动，三类信号连续 20 分钟都没有变化时以 `ENGINE_START_STALLED` 判本次启动失败并按重试规则重建，不再等到启动超时。只对 Docker 和 runveil 上的单机实例生效。
- **卡顿报告**：server 的日志写入或存储操作等待超过 `log.stall_report_after`（默认 3 秒）时记录现场堆栈。见[排障](../how-to/troubleshooting.md#server-卡住或偶发变慢时卡顿报告与现场堆栈)。
- **修改密码**：在控制台右上角的账户菜单选择「修改密码」；修改后该账户的所有会话退出。
- **插件包**：新增 `gpuworks plugin` 子命令，用于校验、安装和移除签名插件包；线上格式见[插件协议与线上格式](../reference/plugin-protocol.md)。

## 变更

- 升级 server 时在**版本与更新**里选择具体版本：同渠道列出已安装版本和后续版本，可按版本号或提交号搜索；从未由渠道发布的分支构建不再显示为已是最新。
- 节点列表默认显示 Agent 版本，并标出待升级、待对齐与构建不同的节点。升级超时的节点记为待确认，5 分钟后不再占用升级名额。
- 网关自己给出的错误统一为 OpenAI 形状并带稳定的 `code`；`GET /v1/models` 只列出此刻能路由的服务名，带范围的 key 只看到它能调用的部署。
- server 正常停止时，正在等休眠部署唤醒的请求返回 503 `SERVER_RESTARTING` 并带 `Retry-After: 10`。
- 启动失败时显示容器退出前的输出和引擎进程抛出的异常；安装、恢复与运行时失败按稳定的码显示原因。
- 手动启用一张卡的调度后，这个决定一直有效，不随卡的后续上报或 server 重启失效。
- Vast.ai 对接更新。（GWKS-348）
- 构建工具链升到 Go 1.26.11。

## 修复

### 升级与安装

- 由 v26.11.0–v26.11.2 的评测历史库升级上来的数据库，镜像系列表缺列，server 启动同步镜像目录时失败、起不来。现在启动时在原位置补上这两步迁移。（GWKS-241）
- 以 root 安装、服务账户运行的控制面，控制台在线升级和上传升级必然回滚：升级后的进程写不进 root 创建的 `install-history.jsonl`，被当成未健康。现在安装时就把这个文件交给服务账户，写不进去也只记一条告警；已出问题的安装用 root 执行一次 `gpuworks upgrade` 即修复。（GWKS-247）
- 直接装在 `/opt/gpuworks` 的控制面无法卸载：卸载在开始前就被拒绝。现在可以卸载，共用的 agent 根目录保留。（GWKS-198）

### 部署与调度

- dGPU 显存上限太小导致实例启动失败时，只显示引擎自己的报错，看不出是上限不够。现在 vLLM 的启动检查、PyTorch 的显存不足、昇腾 vcann-rt 的拒绝和 KV cache 放不下上限，都在实例的失败原因里列出 `DGPU_MEMORY_LIMIT_EXCEEDED`；
  实例自身的错误码仍是 `CONTAINER_EXITED`。（GWKS-423）
- 昇腾共享卡上一个分区启动失败后，平台立即对整张卡做运行时检查，而其他分区正在这张卡上服务；检查失败使整张卡被标为不可调度，直到卡空出来。现在启动失败后的检查跳过其他实例正在服务的卡。（GWKS-425）
- 海光节点上可休眠的 vLLM 部署在宿主机内存不足时，引擎启动中被杀（`EngineCore -9`）：海光的休眠显存池由宿主机内存承载。
  现在创建和评估时以 `SLEEP_HOST_BACKING_INSUFFICIENT` 拒绝，并给出所需与可用内存。（GWKS-428）
- 8 GiB 昇腾 dGPU 分区里的可休眠 vLLM 部署每次启动都以 `NPUCachingAllocator` 错误 300000 退出。可休眠昇腾分区的默认 `gpu_memory_utilization` 现在按显存上限计算（8 GiB 上限为 0.75）；
  新默认值尚未在硬件上实测。（GWKS-427）
- 写成 shell 脚本的手动命令绕过拓扑校验：两张卡的放置上接受 `--tp-size 1`，第二张卡被分配却闲置。现在脚本同样按分配的卡数校验。（GWKS-415）
- TP=1、DP=2 的部署只分到一张卡，启动校验时被拒。现在按引擎 DP 副本数分配卡。
- runveil 负载停止时，被杀的引擎进程还没释放卡就报告已移除，残留进程被当成平台外占用；删除部署后卡有三到四分钟不可调度。现在等被杀进程退出后才报告移除，卡随即可用。（GWKS-432）
- 昇腾 runveil 多卡启动时，逻辑设备号按选卡顺序传入；在逻辑号与物理号顺序不一致的主机上，ACL 运行时以 EE2002 拒绝，多卡启动立即退出。现在按升序传入。（GWKS-418）
- 自动选择 runner 镜像时，910B4 节点被选到 A3（910C）的镜像。现在按节点的昇腾芯片系列选择。
- fp8 KV cache 规则匹配了所有类型名含 deepseek 的模型，DeepSeek-OCR-2 在 PPU 上被加上 `--kv-cache-dtype fp8`，首个请求失败。现在只用于 DeepSeek 的 MLA 模型。（GWKS-493）

### 模型、镜像与存储

- 节点本地盘上的模型副本被手工删除或随节点重装丢失后，仍记录为存在：部署在缺失的目录上连续启动失败三次后停止，节点也不会重新获取模型。
  现在启动前检查以 `MODEL_PATH_MISSING` 报告目录不存在，server 收回这条记录，下一次尝试先重新获取模型。共享存储上的记录不受影响。（GWKS-517）
- 模型源返回一次 429，整个下载在几毫秒内失败，部署一直卡住直到手动重试。现在 429 与 503 按源要求的时间等待后重试，状态显示为被源限速。（GWKS-272）
- 模型下载在最后一个地址反复断开后放弃时，删掉了已下载的部分和续传状态，重试从头开始。现在只在换到另一个地址时才删除。（GWKS-447）
- 同一模型的不同 revision 被写进节点上的同一个目录。现在自动传输的目录按 revision 区分。（GWKS-281）
- 「NFS 加本地缓存」切换为 NFS 后，节点上的缓存目录无人清理，永久残留。现在切换前先清理各节点缓存，还有缓存时以 `STORAGE_CACHE_NOT_EMPTY` 拒绝切换。（GWKS-242）
- 大型 NFS 共享上的存储扫描，某一页在截止时间内没找到模型时返回原游标，扫描停在原地。现在每一页都向前推进。（GWKS-413）
- 硬挂载的 NFS 上一次调用卡死后，该节点上的存储一直显示无响应，要手动 `umount -f -l` 并重启 agent。现在 agent 自己创建的 NFS 挂载上，单次调用卡满 3 分钟即强制卸载并重新挂载。（GWKS-383）
- 周期镜像盘点不上报运行时镜像身份，离线部署拿不到它。（GWKS-238）
- 节点上已有镜像时强制重新获取失败，几秒后周期盘点把状态改回「已存在」并清掉失败原因。现在这次失败及其原因保留可见。（GWKS-246）

### 节点接入与加速卡

- 手工注册的节点没有保存 SSH 凭据，移除时仍尝试 SSH 卸载并失败，节点删不掉。现在没有保存凭据的节点只移除记录，确认前会写明。（GWKS-228）
- 只接受 keyboard-interactive 方式输入密码的主机，SSH 接入失败且只显示库的原始错误。现在接入向导支持这种方式。（GWKS-205）
- 同一网关或 NAT 地址后、只有 SSH 端口不同的第二台主机，接入时以 `NODE_INSTALL_HOST_ALREADY_NODE` 被拒。现在按 SSH 主机加端口识别。
- server 发起连接的节点在探测结束后停在「连接中」，没有重连入口。现在可以手动重连。（GWKS-230）
- 绑定 nouveau 驱动的 NVIDIA 卡显示为被平台外占用，而不是缺少厂商驱动。（GWKS-412）
- dGPU 探针结果为空时，server 提示升级 agent，而不是真实原因。（GWKS-429）
- IPv4 配在 bridge、bond 或 VLAN 上的 RoCE 端口报 `no_ipv4`，不参与网络规划。
- ZStack Cloud 的物理机不满足条件时，安装 agent 只报通用错误。现在按原因说明。

### 内置模板

- DeepSeek-OCR 与 DeepSeek-OCR-2 的 Turing 规格因 vLLM 0.31 拒绝内置的 n-gram logits processor 而无法启动，现改用 V1 runner（`VLLM_USE_V2_MODEL_RUNNER=0`）；尚未在 Turing 卡上实测。（GWKS-485）
- 四个 PPU 规格的 `--chat-template` 路径在 PPU runner 里解析不到，其中三个每次启动都失败：两个把权重目录写成了 `/models/<org>/<repo>`（权重挂载在 `/model`），两个 Gemma 4 规格引用的示例模板没有确认镜像别处是否自带。现在都指向挂载权重里的模板文件；Gemma 4 改用权重自带的模板后，工具定义和工具结果的渲染可能有变化。尚未在 PPU 节点上实测。（GWKS-484）
- Qwen3.5-27B 的 PPU 规格按引擎默认的 1024 个序列启动失败，现限制为 256；尚未在 PPU 节点上实测。（GWKS-486）
- 移除 LLaDA2.1-mini 的 PPU 规格：PPU runner 自带的 FlashInfer 版本低于 SGLang 扩散路径的要求，启动必然失败。该模型在 NVIDIA 上仍可用。（GWKS-430）
- 19 个目录模型的 ModelScope 来源钉的是 Hugging Face 的提交号，下载返回 404。（GWKS-410）
- HunyuanOCR 的 NVIDIA 规格从 ModelScope 下载权重后，vLLM 报 tokenizer 缺少 `image_token`；已去掉这个来源。（GWKS-436）
- 海光 Qwen3-TTS 规格的镜像里没有 vllm-omni，容器以 127 退出，已移除；三个海光视觉规格拉取不存在的 `latest` 镜像，已恢复原来的镜像引用。（GWKS-374）
- Qwen3-Reranker-8B 声明了会失败的 chat 接口，现在只声明 rerank；其 NVIDIA 规格改用 SGLang 的 reranker 模板。（GWKS-352）
- 昇腾上的 MiniCPM 被放到装不下初始化峰值的单张 32 GiB 卡上。现在放置时拒绝。（GWKS-351）
- Gemma 3 27B 的 910B SGLang 规格在图模式下首次生成时崩溃，改为 eager 运行。（GWKS-354）
- 海光 Qwen3.5-35B-A3B 的 chat 返回空内容：模型先思考，思考内容不在 `content` 里。规格默认关闭思考。（GWKS-373）

### 控制台、监控与接口

- 指标库只有一个连接，范围查询期间 agent 上报的指标写不进去；保留期调长后一次查询可挡住写入数秒。现在查询走只读连接池。（GWKS-240）
- 非流式压测请求带了 `stream_options`，严格的 OpenAI 兼容服务返回 400。（GWKS-330）
- 个人推理 key 读不到同一用户在控制台创建的批处理任务。（GWKS-317）
- AI 助手的节点巡检在 jq 过滤器对不上时失败。现在仍返回正文和原因。（GWKS-239）
- 导出的日志 CSV 没有 BOM，在 Excel 里中文乱码。（GWKS-367）
- 同步组限速填 0 被悄悄存成 0.01 MB/s。现在拒绝这个值。（GWKS-297）
- 实时日志流被拒后，面板一直停在「等待日志」。现在显示被拒的原因。

## 安全

- `/v1` 是否接受不带 key 的请求改为显式的安全设置，默认关闭，不再取决于库里有没有 key；设置读取失败时按关闭处理。
- 本版新增的插件宿主使用 `golang.org/x/net` v0.60.0，其中已修复 HTTP/2 实现的 GO-2026-6603、GO-2026-6610、GO-2026-6611、GO-2026-6612、GO-2026-6617。26.11 各版本不含插件宿主，也不依赖这个库，不受影响。（GWKS-419）
- 使用 Go 1.26.11 构建，修复 `net/http` 的 GO-2026-6859：请求体超限与响应头写入并发时可能 panic。（GWKS-233）
