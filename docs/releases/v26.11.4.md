# v26.11.4

发布日期：2026-11-18 · 发布线：26.11

这一版修复 SGLang 实例在长时间 prefill 时被当成无响应回收的问题（PD 分离部署里表现为 decode 报 "Lost connection with prefill instance"），
并让 server 容错读取官方推理模板目录：本版本读不懂的模型与档位跳过并列出，其余照常更新，不再整包失败。使用 SGLang（尤其是 PD 分离）的 26.11 用户建议升级。本版没有数据库迁移。

## 升级须知

- **先升级 server，再升级 agent**：运行中实例的存活判定在 agent 一侧，需要 agent 也升级到 v26.11.4；SGLang 的启动环境变量随 server 更新。
- **SGLang 实例重新部署后才带上新环境变量**：server 生成的 SGLang 启动配置新增 `SGLANG_ENABLE_HEALTH_ENDPOINT_GENERATION=0`，只对新建或重建的实例生效，已在运行的实例保持原样。
  模板或部署里显式设置的同名环境变量仍然优先。
- **用户自己导入的模板仍严格校验**：容错只用于官方目录（「检查更新」与设置页上传）；推理模板页的「导入模板」遇到读不懂的字段仍整体拒绝。

## 变更

- SGLang 的 `/health` 不再经调度器生成一个 token：server 为 SGLang 实例设置 `SGLANG_ENABLE_HEALTH_ENDPOINT_GENERATION=0`，`/health` 只反映进程是否在服务。
  此前长 chunked prefill 期间 `/health` 等不到调度器输出而超时。
- 实例进入 running 后，agent 的健康检查要连续失败 3 分钟才回收实例（此前约 13 秒内三次失败即回收）；容器退出仍立即按退出处理。
- 官方推理模板目录改为容错读取：本版本解析或校验不了的模型与档位被跳过并在设置页列出，库里已有的对应档位保持原样、仍可使用，其余内容照常更新。
- 可以读取第 3 版目录包格式（带 `gpus.arch_id`、`tokenizer_ref` 的目录）；本版内嵌目录仍为第 2 版，v26.11.0–v26.11.3 照常读取。
- 模板中的平台变量接受 `GPUWORKS_` 前缀，例如 `${GPUWORKS_API_PORT}` 等同于 `${API_PORT}`。

## 修复

- SGLang 实例在长时间 prefill 时被 agent 判为无响应并回收；PD 分离部署中 decode 随之报 "Lost connection with prefill instance"。（[#30](https://github.com/flitai-io/gpuworks/issues/30)）
- 官方推理模板目录只要有一个模型使用了本版本不认识的字段，「检查更新」与上传就整包失败，提示需要更新的 server。
