# v26.11.3

发布日期：2026-11-12 · 发布线：26.11 · 提交：`1335143d3`

这一版修复海光 DCU 的两个部署问题：只报系列 `BW` 的卡匹配不到内置模板，以及 Docker / nerdctl 下选中非 0 号卡的实例找不到 GPU；
另修复部署表单在指定模型与权重来源不一致时被拒。使用海光 DCU 的 26.11 用户建议升级。本版没有数据库迁移。

## 升级须知

- **先升级 server，再升级 agent**：海光卡号修正在 agent 一侧，需要 agent 也升级到 v26.11.3；内置模板的适用卡范围随 server 更新。
- **海光内置模板的适用范围扩大**：K100 / K100_AI 上实测通过的内置海光档位，现在同样适用于整个 BW 系列（只报系列的 `BW`，以及 BW100、BW150、BW1000、BW1100 等）。
  除 Qwen3-0.6B 外，这些档位尚未在 BW 上逐一实测；从内置模板复制出的自定义模板保留原来的适用范围，需要时手动修改。

## 变更

- 内置海光档位的 GPU 名称谓词由 `BW1000` / `BW1100` 扩展为整个 BW 系列。`hy-smi --showproductname` 在部分驱动上只报 `Card Series: BW`，
  此前这类节点被所有内置海光档位拒绝。
- 手动安装文档改为下载最新正式版，不再指向 nightly 构建。

## 修复

- 海光节点上 `hy-smi` 只报 `BW` 的卡，部署内置模板时提示"没有 GPU 通过部署硬件检查"。（[#10](https://github.com/flitai-io/gpuworks/issues/10)）
- Docker 与 nerdctl 只把所选卡交给海光容器，容器内 HIP 从 0 开始编号，agent 却按宿主卡号设置 `HIP_VISIBLE_DEVICES` / `HYGON_VISIBLE_DEVICES`，
  选中 0 号以外的卡时引擎报 `No HIP GPUs are available`。runveil 绑定整个宿主 `/dev`，保持宿主卡号。
- 部署表单同时带着所选模型和与之不同的权重来源时，评估与创建被拒为来源冲突；现在以所选模型为准。（GWKS-234）
