# v26.11.4

Released 2026-11-18 · Release line 26.11 · Commit `2cfc198e6`

This release stops SGLang instances from being retired as unresponsive during long prefills (in PD disaggregated deployments this showed up as decode reporting "Lost connection with prefill instance"),
and makes the server read the official inference template catalog tolerantly: models and specs this release cannot read are skipped and listed, the rest updates as usual instead of the whole package failing. 26.11 users running SGLang, PD disaggregation in particular, should upgrade. This release has no database migration.

## Upgrade Notes

- **Upgrade the server first, then the agents**: the liveness decision for running instances is made by the agent, so agents must also move to v26.11.4; SGLang's launch environment comes with the server.
- **SGLang instances pick up the new variable only when redeployed**: the SGLang launch configuration the server generates now sets `SGLANG_ENABLE_HEALTH_ENDPOINT_GENERATION=0`. It applies to new or rebuilt instances; running ones are left as they are.
  A variable of the same name set explicitly in a template or deployment still wins.
- **Your own template imports stay strict**: tolerance applies only to the official catalog (Check for updates and the upload on the settings page); Import templates on the inference templates page still rejects a package with fields it cannot read.

## Changed

- SGLang's `/health` no longer generates a token through the scheduler: the server sets `SGLANG_ENABLE_HEALTH_ENDPOINT_GENERATION=0` for SGLang instances, so `/health` reflects only whether the process is serving.
  Before, `/health` timed out during long chunked prefills while it waited for scheduler output.
- Once an instance is running, the agent retires it only after its health check has failed continuously for 3 minutes (before, three failures within about 13 seconds retired it); a container exit is still handled immediately.
- The official inference template catalog is read tolerantly: models and specs this release cannot parse or validate are skipped and listed on the settings page, specs already in the database for them stay as they are and remain usable, and everything else updates as usual.
- Catalog package format 3 (catalogs with `gpus.arch_id` and `tokenizer_ref`) can be read; the catalog embedded in this release stays at format 2, so v26.11.0–v26.11.3 keep reading it.
- Platform variables in templates accept the `GPUWORKS_` prefix: `${GPUWORKS_API_PORT}` means the same as `${API_PORT}`.

## Fixed

- SGLang instances were judged unresponsive by the agent and retired during long prefills; in PD disaggregated deployments decode then reported "Lost connection with prefill instance". ([#30](https://github.com/flitai-io/gpuworks/issues/30))
- One model in the official inference template catalog using a field this release did not know made Check for updates and the upload fail for the whole package, asking for a newer server.
